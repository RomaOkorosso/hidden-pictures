# Критерии готовности и проверка

Каждому пункту в итоговом отчёте поставить PASS / FAIL / BLOCKED / NOT TESTED и приложить конкретное свидетельство: команда с результатом, test name, проверенный URL. «Кажется работает» и «должно работать» не свидетельства.

## Минимальный сквозной сценарий

1. Четыре независимых контекста браузера регистрируются/входят разными пользователями, один создаёт комнату, остальные входят по ссылке и коду.
2. Случайное распределение даёт две команды и двух разных капитанов. Старт с неполным составом блокируется. Ручное назначение и конфликт одновременного занятия капитанского места обработаны.
3. Поле 20 уникальных карт; ключ имеет 8/7/4/1. Оба капитана видят ключ, оба угадывающих не получают его через SDK, REST, родительское чтение, DOM и публичное состояние.
4. Капитан даёт подсказку, все видят её. Своё открытие уменьшает нужный счёт и попытки; нейтральная/чужая завершает ход. Капитан другой команды не может отправить подсказку вне очереди.
5. На подсказку N допустимо максимум N+1 открытий. Ручное завершение после первого открытия работает. До первого открытия не работает.
6. Убийца, последний свой агент и последний чужой агент дают правильного победителя и блокируют дальнейшие действия. Публичный доступ к ключу разрешается после завершения, но не до.
7. Повторный tap, два конкурентных клика одной карточки, разных карточек и нейтрали/убийцы одновременно не расходятся между клиентами. Запросы прошлого хода и прошлой партии отвергаются.
8. Перезагрузка угадывающего, потеря и возврат сети, закрытие вкладки хоста восстанавливаются без новой раздачи и без потери результата. Две вкладки одного UID не создают двух игроков.
9. Новая партия работает с новым ID и ключом. Выход/удаление из лобби не оставляет доступ к будущим секретам. Нельзя стать угадывающим после знания ключа активной партии.
10. Invite deep link работает после reload на Pages subpath. Смена RU/EN сохраняется, не ломает состояние.

## Автоматические проверки

- Unit: reducer/state machine, генерация и состав ключа, раздача без дубликатов, все окончания игры, N+1, число игроков/ролей, обработка stale action.
- Rules: отдельные авторизованные UID обеих команд/капитанов, владелец-угадывающий, посторонний, удалённый участник и неавторизованный клиент. Прямые разрешённые и запрещённые чтения/записи; не только UI.
- Concurrency: две подсказки, двойной старт, двойное reveal, смена хода при in-flight запросе, retry после reconnect, конфликт версии. Проверять итог и число принятых действий.
- Integration/E2E: минимум четыре независимых auth/browser contexts с настоящими emulator Auth+RTDB и реальным UI, не общим localStorage mock. Полная партия может использовать детерминированный fixture ключа только в тесте; production не импортирует fixture.
- Assets: каждый путь manifest существует, ID уникальны, изображений >=20, WebP декодируются, квадратные размеры, правильный URL на subpath. Проверить отсутствие концепт-подсказок в игровой разметке.
- Build: воспроизводимая установка по lockfile, typecheck, lint, build. Production bundle не содержит admin secrets, тестовых ключей партии, подключения к emulator.

## Визуальная проверка

Viewport 360×800, 390×844, 768×1024, 1366×768. Проверить регистрацию, лобби 12 игроков с длинными именами, игровое поле, капитанский ключ, увеличение картинки, модал подтверждения, reconnect и результат. Нет перекрытия кнопок, горизонтального скролла страницы, незакрываемых модалок или скрытого подсказкой поля. Увеличение картинки не открывает её. Клавиатура, focus styles, Escape, контраст и подписи кнопок работают. Не запрещать доступный zoom браузера целиком.

## Production и сдача

- Последний workflow default branch зелёный, URL открывается по HTTPS.
- С реальными Firebase config и Rules подтверждены login, создание/вход в комнату, realtime и капитанский доступ. Не создавать лишние реальные аккаунты ради теста, если нет полномочий/условий: тогда эту часть честно пометить NOT TESTED и дать минимальный конкретный smoke check владельцу.
- Свежий checkout запускается по README одной командой после `npm ci` с emulator либо после копирования `.env.example` с уже полученными значениями.
- Короткая инструкция обновления карточек, деплоя Rules, смены конфигурации, восстановления и удаления старых комнат.
- Нет обязательного TODO в регистрации, сетевой игре, правилах, security или deploy. Остаточные улучшения только косметические и необязательные.

## Если обнаружен непреодолимый блокер

Не выдавать фальшивый PASS. Сначала исчерпать доступные обратимые исправления и подготовить всё независимое. Записать точную ошибку без токенов, действие/страницу для владельца, что уже готово и с какой команды агент продолжит после входа. Не заменять backend обещанием «позже настроим». Готовый offline demo не равен законченной online игре.
